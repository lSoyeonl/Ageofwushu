# Легенды Кунг-Фу 0.0.44 — GitHub Pages + Supabase

## 1. Создайте проект Supabase
Создайте новый проект Supabase и дождитесь завершения его настройки.

## 2. Создайте таблицы и правила
Откройте **SQL Editor** в Supabase, вставьте весь файл `supabase-schema.sql` и выполните его.

Скрипт создаёт:
- `profiles` — профили пользователей и роли `user/admin`;
- `site_store` — общий контент сайта;
- bucket `site-images` — изображения;
- RLS-политики;
- Realtime для обновления контента.

## 3. Настройте `supabase-config.js`
В Supabase откройте настройки API проекта и скопируйте:
- Project URL;
- Publishable key или anon key.

В файле `supabase-config.js` замените:

```js
url: "https://YOUR_PROJECT_ID.supabase.co",
anonKey: "YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY",
adminEmail: "YOUR_ADMIN_EMAIL@example.com",
```

`service_role` key в GitHub Pages использовать нельзя.

## 4. Создайте администратора
В Supabase Authentication создайте пользователя с вашим реальным e-mail.

После этого выполните в SQL Editor:

```sql
update public.profiles
set role='admin'
where email='ВАШ_EMAIL';
```

Тот же e-mail укажите как `adminEmail` в `supabase-config.js`.

После этого на странице `admin-login.html` можно вводить:
- логин: `admin`
- пароль: пароль созданного Supabase-аккаунта администратора.

## 5. Настройки Authentication
В Supabase Authentication -> URL Configuration укажите URL вашего GitHub Pages сайта.
Для подтверждения e-mail добавьте адрес страницы `account.html` в разрешённые Redirect URLs.

Если подтверждение e-mail включено, после регистрации пользователь сначала подтверждает адрес из письма, затем входит на сайт.

## 6. GitHub Pages
Загрузите содержимое архива 0.0.44 в репозиторий и включите GitHub Pages.
Никакой `START_SITE.bat` не нужен.

## 7. Перенос старого контента
Если у вас есть JSON backup из v35, войдите администратором -> **Резервные копии** ->
**Импортировать старый JSON**.

Будет перенесён контент. Старые localStorage-аккаунты автоматически в Supabase Auth не переносятся.
Пользователи должны зарегистрироваться в новой центральной системе либо мигрироваться отдельно через защищённый серверный скрипт с service-role ключом.

## Резервные копии
Страница `admin-backups.html` умеет:
- экспортировать `site_store` и `profiles` в JSON;
- импортировать контент обратно.

Для полного восстановления Supabase Auth пользователей используйте резервное копирование самого проекта/БД Supabase.
Клиентский GitHub Pages сайт не получает service-role доступ и не должен уметь экспортировать пароли или `auth.users`.

- сайт адаптирован под телефон, планшет и компьютер;

- изображения автоматически оптимизируются и отправляются в Supabase Storage;
- изображения можно вставлять прямо в rich-text и ячейки таблиц;

- в «Обновлениях» исправлено изображение и добавлена «Награда» для промокода.

## Исправление 0.0.44
- «О Тайвани» и «О Пиратке» теперь публикуют запись только после завершения сохранения в общей базе;
- страницы читают актуальный ключ контента напрямую, а не устаревшую копию `kungfuPublicDataV1`;
- изображения в галерее и внутри текста перед публикацией могут быть преобразованы в URL Supabase Storage;
- при ошибке сохранения материал не исчезает молча — показывается сообщение.


## Дополнения 0.0.44
- длинные материалы в «Обновлениях», «О Тайвани» и «О Пиратке» больше не ограничены квотой localStorage;
- если центральная синхронизация Supabase ещё не подключена, большие публикации сохраняются в IndexedDB текущего браузера;
- при настроенном Supabase браузерный cache quota больше не отменяет успешную публикацию;
- изображения внутри редактора можно выделить кликом и изменить размер относительно текста;
- размеры шрифта в rich-editor: от 5 до 30 px;
- в «Обновлениях» награды стали неограниченным списком ✔️;
- блок «Дата / Период» визуально усилен.


### Финальная проверка 0.0.44
- публичные страницы регистрации и входа больше не показывают техническое сообщение с именем `supabase-config.js`;
- при отсутствии Supabase включается локальный fallback, чтобы форма не ломалась;
- для одного аккаунта на разных устройствах всё равно необходимо заполнить `supabase-config.js`;
- переполнение `localStorage` не отменяет успешное сохранение общего контента в Supabase;
- «Продажа Аккаунтов» и «Форум» используют IndexedDB как резерв для больших изображений/материалов;
- раздел «Контакты» переименован в «Партнеры».
